# Weed segmentation to Gazebo path

Standalone code to train the weed segmenter, predict one field image, and export
a CSV waypoint path for manual use in Gazebo. It does not command or arm a drone.

## What the commands do

- `conda activate base` selects the Conda environment that already has PyTorch and CUDA.
- `pip install -r requirements.txt` installs PyTorch, NumPy, and OpenCV.
- The training command learns from WeedMap images and saves a checkpoint.
- The prediction command writes a weed mask and a coordinate path CSV.

## Files needed

The code and requirements are already in this folder:

- `scripts/train_model.py`, `scripts/predict_image.py`
- `src/weed_uav_pipeline/` (model, training, inference, and path conversion)
- `requirements.txt`

To train on another machine without the original FYP folder, also place the
matching WeedMap files under `data/WeedMap/RedEdge/`, preserving the flight
folders. For each frame include:

- `<flight>/tile/RGB/frameXXXX.png` - RGB model input.
- `<flight>/groundtruth/<flight>_frameXXXX.png` - source mask used for the
  under-40%-black tile filter.
- `<flight>/groundtruth/<flight>_frameXXXX_GroundTruth_color.png` - color
  annotation used to make the weed/background target.

Example for flight 000, frame 0000:

```text
data/WeedMap/RedEdge/000/tile/RGB/frame0000.png
data/WeedMap/RedEdge/000/groundtruth/000_frame0000.png
data/WeedMap/RedEdge/000/groundtruth/000_frame0000_GroundTruth_color.png
```

Include all matched frames wanted for training and validation; include at least
two flight folders when possible so validation can hold out full flights.
Not needed: FYP notebooks, PDFs, camera or drone scripts, the `mask/` folder,
and non-RGB spectral bands.

You can leave FYP data in Downloads and pass its path to training. To bundle the
whole RedEdge tree inside this folder (this includes unused spectral bands):

```sh
mkdir -p data/WeedMap
cp -a /mnt/c/Users/yashraj/Downloads/FYP/Tiles/RedEdge data/WeedMap/
```

For a lean bundle, copy only the three matching files per frame above and keep
their folder structure. A trained checkpoint is generated by training; it is
not required in order to train.

## Use your existing Conda base environment

```sh
conda activate base
cd /home/weed_uav_pipeline
python -m pip install -r requirements.txt
```

## Train

If the FYP data remains in Downloads:

```sh
python scripts/train_model.py \
  --data-root /mnt/c/Users/yashraj/Downloads/FYP/Tiles/RedEdge \
  --output checkpoints/weed_unet.pt
```

If copied into this folder:

```sh
python scripts/train_model.py \
  --data-root data/WeedMap/RedEdge \
  --output checkpoints/weed_unet.pt
```

Training uses float32 ExG, ExGR, and CIVE features and the notebook's
red-to-weed annotation mapping. It holds out complete flights for validation
when possible, reports weed IoU/precision/recall, and saves the best validation
checkpoint to `checkpoints/weed_unet.pt`.

Training automatically uses the GPU when PyTorch can access CUDA; otherwise it
uses the CPU. At startup, check that the training output says `device: cuda`.
To check CUDA in this environment first, run:

```sh
python -c "import torch; print(torch.cuda.is_available())"
```

## Predict and export a Gazebo path

Copy a top-down RGB field image into this folder as `field.png`, then run:

```sh
python scripts/predict_image.py \
  --checkpoint checkpoints/weed_unet.pt \
  --image field.png \
  --field-width-m 10 --field-height-m 10 \
  --grid-rows 3 --grid-cols 3 --min-weed-fraction 0.05 \
  --altitude-m 2.5
```

It creates `output/field_weed_mask.png` and `output/field_path.csv`. The CSV
contains visit order, grid row/column, x/y/z in meters, and weed fraction.
Mask value 0 means weed; 255 means other. Cells below the threshold are omitted.

Coordinates assume the image shows the whole rectangular field from above:
image row zero is the far (+y) edge, x increases right, and y increases up.
Set field size and origin to match Gazebo. The CSV is for manual simulation.

## Standalone bundle checklist

1. Include this entire `/home/weed_uav_pipeline` folder.
2. Include matched WeedMap files under `data/WeedMap/RedEdge` if the recipient
   must train without the original FYP folder.
3. Include `checkpoints/weed_unet.pt` if the recipient should predict without
   training first.
4. Include `field.png` only if you want a runnable example image.

Install requirements in the recipient's Python environment. No other files
from the clone or FYP are needed by the code.
